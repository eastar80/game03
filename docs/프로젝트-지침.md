# 중독성 있는 간단한 게임 — 프로젝트 지침

이 프로젝트는 브라우저에서 바로 실행되는 짧은 원버튼/원스킬 게임을 만든다.
지침은 실험 결과로 계속 고친다. 규칙이 틀렸다고 판명되면 지우고, 이유를 "실험 기록"에 남긴다.

## Claude의 역할

- 게임 아이디어가 나오면 먼저 **아래 디자인 원칙에 비추어 판단**하고, 통과하지 못하면 만들기 전에 말한다.
- 특히 원칙 1·2(실력이 결정하고, 실력이 즉시 느껴지는가)를 가장 먼저 검사한다.
- 기능을 더 붙이자는 제안이 나오면 코어 루프가 재미있다고 확인되었는지 먼저 묻는다(원칙 9).
- 코드를 쓸 때는 아래 기술 컨벤션을 따른다. 어길 때는 이유를 적는다.
- 완성된 게임은 실험 기록 표에 한 줄로 평가를 남기고, 원칙을 고칠 근거가 되면 제안한다.

## 게임 디자인 원칙

1. **결과는 실력이 결정한다.** 랜덤은 상황(배치, 색, 시작 위치)만 바꾸고 결과를 정하지 않는다.
   점수에 영향을 주는 난수가 없어야 한다 — 입력 기록만으로 게임이 그대로 재현되어야 한다.
2. **실력은 통계가 아니라 몸으로 느껴져야 한다.** 100판 평균에서 차이가 나는 것은 실력이 아니다.
   입력 후 1초 안에 "내가 잘해서/못해서 이렇게 됐다"가 화면에 보여야 한다.
   입력과 결과 사이에 긴 물리 시뮬레이션, 여러 단계의 계산, 턴 대기가 끼면 그 연결은 끊긴다.
3. **한 가지 입력, 한 가지 스킬.** 탭/스페이스 하나로 조작하고, 게임이 시험하는 능력은 하나다
   (타이밍, 리듬, 판단 등). 설명 없이 3초 안에 이해되어야 한다.
4. **실패가 즉각적이고 명확하다.** 왜 죽었는지 화면에서 바로 보인다.
5. **짧은 코어 루프.** 한 판 30초~2분. 재시작은 탭 한 번, 1초 이내.
6. **넘어야 할 숫자가 플레이 중 보인다.** 최고 기록/순위는 게임 오버 뒤가 아니라 플레이 중에.
7. **주스(juice)를 아끼지 않는다.** 화면 흔들림, 콤보 상승음, 파편 등 피드백은 강하게.
   단, prefers-reduced-motion 을 존중한다.
8. **위험-보상 축이 있다.** 예: PERFECT 판정이 좁을수록 보너스가 크고 폭이 회복된다.
   (stacker 하나에서 나온 가설. 다음 게임에서 확인 필요)
9. **시스템은 하나만.** 덱, 유물, 적 주기, 층 진행처럼 시스템이 겹치면 프로토타입에서
   무엇이 재미를 만들고 무엇이 망치는지 알 수 없다. 코어 루프가 재미있다고 확인된 뒤에만 붙인다.

## 기술 컨벤션 (stacker 에서 검증됨)

- 정적 HTML 단일 파일(`index.html`), 빌드 없음. 프로토타입 단계에서는 분리하지 않는다.
- 외부 라이브러리·에셋 없음. Canvas 2D + Web Audio 합성(음원 파일 없음).
- 모든 움직임은 `dt` 를 곱한다(60fps 기준 환산, [0, 3] 클램프). 주사율에 따라 게임이 달라지면 안 된다.
- 오디오는 사용자 제스처 이후 시작.
- 저장은 어댑터로: `window.storage` → `localStorage` → 메모리 폴백.
- 난이도는 표(`DIFFS`) 하나로 정의한다. 튜닝은 그 표만 고친다.
- UI 텍스트는 한국어.
- GitHub Pages 자동 배포(`main` 푸시). 온라인 리더보드는 Supabase REST 를 `fetch` 로 직접 호출한다.

## 작업 방식

- 새 게임은 먼저 **한 문장 규칙 + 한 문장 스킬**을 적고 시작한다.
  (예: "움직이는 블록을 탭으로 놓는다 / 시험하는 것은 타이밍")
- 저장소마다 `CLAUDE.md`(구조·컨벤션)와 `README.md`(규칙·수치·이유)를 둔다.
- **자동 플레이 테스트는 유지한다**(2nd-game 의 `window.__peg` 훅 + Playwright 방식).
  단, 그 수치는 밸런스 확인용이지 재미의 증거가 아니다. 재미는 직접 10판 해보고 판단한다.
- 완성 후 아래 표에 평가를 남긴다.

## 실험 기록

| 게임 | 스킬 | 결과 | 교훈 |
|------|------|------|------|
| stacker | 타이밍 | 성공 | 판정 폭·회복량으로 난이도 조절이 잘 됨. 콤보가 "한 판 더"를 만든다. 원칙 1·5·8의 근거 |
| 2nd-game (페그 드롭 로그라이크) | 조준 | 실패 | 조준 실력이 통계로는 승률 7배 차이를 냈지만(3%→22%) 플레이어는 느끼지 못했다. 한 발 4~8.5초의 물리를 구경하고, 첫 튕김 뒤는 카오스이며, 데미지→배율→공격 4단계를 거쳐 결과가 나온다. 시스템(덱·유물·적 7종·10층)이 코어 루프 검증 전에 너무 많았다. 원칙 2·9의 근거 |
