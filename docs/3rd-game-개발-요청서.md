# 3rd-game 「골라!」 개발 요청서

> 이 문서는 프로젝트 지침(`프로젝트-지침.md`)을 전제로 한다. 충돌하면 지침이 우선이고, 어긴 곳은 `README.md`에 이유를 적는다.

## 0. 한 문장

- **규칙:** 위에서 떨어지는 도형 중 지금 조건에 맞는 색만 탭한다. 아닌 것은 그냥 보낸다.
- **스킬:** 억제(누르지 말 것을 참기) + 반응.

## 1. 이 게임이 검증하는 가설

1. **원칙 8(위험-보상 축)** — 높은 곳에서 탭할수록 배율이 크다. 콤보 없이 이 축 하나만으로 "한 판 더"가 생기는가.
2. **원칙 2** — 타이밍 외의 스킬(판단)도 입력 후 0.1초 안에 "내가 잘해서/못해서"가 보이는가.

콤보·덱·유물·스테이지 등 **다른 시스템은 넣지 않는다**(원칙 9). 제안하고 싶으면 코드 대신 README에 적는다.

## 2. 코어 루프

### 2.1 화면
- 논리 해상도 360×640, Canvas 2D. 창 크기에 맞춰 레터박스 스케일.
- 세로 한 줄(레인 하나). 도형은 상단(-40px)에서 생성되어 바닥(y=600)으로 떨어진다.
- 화면 상단 고정 HUD (플레이 중 항상 보임, 원칙 6):
  - 왼쪽: 목숨 ♥♥♥
  - 중앙: **현재 조건** — 큰 색 원 + 텍스트 "파랑". 조건은 색 하나다.
  - 오른쪽: 점수 / 그 아래 작게 `최고 12,340`
  - 점수가 최고를 넘는 순간 HUD 최고점이 현재점으로 바뀌며 금색 플래시 + 짧은 상승음.
- 레인 배경에 세 구역이 옅게 표시된다: 상단(×3) / 중단(×2) / 하단(×1). 구역 경계 y: 0–200 / 200–400 / 400–600.

### 2.2 도형
- 색 4종: 파랑 `#3B82F6`, 빨강 `#EF4444`, 노랑 `#FACC15`, 초록 `#22C55E`. 모양은 원 하나로 고정(모양은 스킬에 관여하지 않는다).
- 색맹 보조: 각 색에 작은 내부 기호를 함께 그린다(파랑 ●, 빨강 ▲, 노랑 ■, 초록 ◆). 조건 HUD에도 같은 기호.
- 한 번에 화면 위 여러 개가 있어도 **활성 도형은 가장 아래 하나**만. 활성 도형은 테두리가 밝게 빛난다. 탭은 항상 활성 도형에 적용된다.

### 2.3 판정
탭 순간 활성 도형 `s`, 현재 조건 `c`:

| 상황 | 결과 | 피드백 |
|---|---|---|
| 탭, `s.color === c` | **HIT** +10 × 구역 배율 | 아래 3.1 |
| 탭, `s.color !== c` | **WRONG** 목숨 −1 | 아래 3.2 |
| 탭 없음, 조건 도형이 바닥 도달 | **MISS** 목숨 −1 | 아래 3.3 |
| 탭 없음, 비조건 도형이 바닥 도달 | **PASS** +0 | 도형이 작게 흩어지며 사라짐, 아주 짧은 낮은 톡 소리 |

- 구역 배율은 **탭 순간 도형 중심의 y**로 결정. 상단 ×3, 중단 ×2, 하단 ×1.
- 활성 도형이 없을 때(공백 구간) 탭은 무시. 벌점 없음. HUD 조건이 살짝 흔들려 "지금은 아무것도 없음"을 알림.
- 목숨 0 → 게임 오버.

### 2.4 조건 전환
- 조건은 `DIFFS[level].switchEvery`개의 도형이 지나갈 때마다 바뀐다(정확한 시점은 시드로 결정, 아래 5장).
- 새 조건은 이전과 다른 색.
- 전환 순서: 마지막 도형이 처리된 뒤 **1.2초 동안 도형 생성 없음** → 화면 중앙 큰 배너 `→ 빨강` (새 색으로 채운 큼직한 원 + 텍스트) 0.8초 → HUD 조건이 새 색으로 바뀜 → 생성 재개.
- 전환 중 화면에 남아있는 도형은 없다(공백을 먼저 두므로). 판정 조건이 애매해지는 순간이 없어야 한다.
- 전환 시 짧은 두 음 알림(낮→높).

### 2.5 흐름
- 시작 화면: 제목 「골라!」, 한 줄 설명 "조건 색만 탭 · 높이 탭하면 ×3", `탭해서 시작`. 첫 탭이 AudioContext 시작.
- 게임 오버: 점수 / 최고 / 이번 판 HIT·WRONG·MISS 개수 / 구역별 HIT 분포(×3, ×2, ×1 각 n개). 배경에 마지막 실패 도형이 붉게 남아있다. **탭 한 번**으로 즉시 재시작, 1초 이내.
- 한 판 목표 길이 45초~90초. `DIFFS`로 맞춘다.

## 3. 피드백(주스) — 아끼지 말 것

모두 `prefers-reduced-motion: reduce`이면 흔들림·확대·파편은 끄고 색·텍스트·소리만 남긴다.

### 3.1 HIT
- 도형이 그 자리에서 터져 12~20개 파편(도형 색)으로 흩어진다.
- 탭 위치에 `×3` / `×2` / `×1` 텍스트가 튀어 오른다. ×3은 크고 금색, ×2 은색, ×1 흰색·작게.
- 소리: 구역별 음높이 3단(×1 낮음 → ×3 높음). 사인+삼각 합성, 80ms.
- ×3일 때만 화면이 아주 살짝(2px) 튄다.

### 3.2 WRONG
- 게임을 **250ms 정지**한다. 정지 중: 눌린 도형이 1.6배로 커지고 붉은 테두리, 옆에 `✕ 이건 빨강` (그 도형의 실제 색 이름).
- 화면 전체 붉은 플래시 120ms + 흔들림 6px.
- HUD 하트 하나가 깨지며 떨어진다.
- 소리: 낮고 둔탁한 노이즈 버스트 150ms.

### 3.3 MISS
- 도형이 바닥에 닿아 납작해지고 갈라진다. 위에 `놓침` 텍스트.
- 화면 흔들림 4px, 하트 깨짐, 소리는 WRONG보다 짧고 건조하게.

### 3.4 기타
- 최고 기록 갱신: 금색 플래시 + 상승 아르페지오 3음.
- 조건 전환: 배너 등장 시 배경색이 새 조건 색으로 아주 옅게(알파 0.08) 물든다.

## 4. 난이도 — `DIFFS` 표 하나

레벨은 **처리된 도형 수** 기준으로 오른다. 튜닝은 이 표만 고친다.

```js
const DIFFS = [
  // upTo: 이 개수까지 이 레벨. speed: px/frame(60fps 기준). gap: 생성 간격(프레임).
  // lure: 비조건 도형 비율. switchEvery: 조건 전환까지 도형 수.
  { upTo:  15, speed: 3.0, gap: 55, lure: 0.40, switchEvery: 12 },
  { upTo:  35, speed: 3.6, gap: 48, lure: 0.45, switchEvery: 10 },
  { upTo:  60, speed: 4.2, gap: 42, lure: 0.50, switchEvery:  9 },
  { upTo:  90, speed: 4.9, gap: 37, lure: 0.55, switchEvery:  8 },
  { upTo: 130, speed: 5.6, gap: 33, lure: 0.60, switchEvery:  7 },
  { upTo: Infinity, speed: 6.3, gap: 30, lure: 0.60, switchEvery: 6 },
];
```

- 상단 구역(200px)을 지나는 시간이 `speed 3.0`이면 약 1.1초, `6.3`이면 0.53초 → ×3 노리기의 위험이 레벨과 함께 커진다.
- 이 값들은 초안이다. 자동 봇(7장)으로 "완벽 봇 90초 이상 생존, 반응 300ms 봇 45~75초 생존" 정도가 나오게 맞춘다.

## 5. 재현성(원칙 1)

- PRNG는 `mulberry32(seed)`. `Math.random`은 게임 로직에서 금지(파편 연출에만 허용).
- 시드가 결정하는 것: 도형 색 순열, 조건 색, 조건 전환 시점. **시드가 결정하지 않는 것: 결과.**
- 매 판 `seed`와 입력 로그 `[{t: 게임시간ms}]`를 기록한다.
- 게임 오버 화면에 `시드 · 재현` 작은 버튼: `window.__judge.replay(seed, inputs)`로 같은 판을 그대로 재생하고, 점수가 같은지 콘솔에 표시. 이게 통과하지 않으면 원칙 1 위반이다.

## 6. 저장·리더보드

- 저장 어댑터: `window.storage` → `localStorage` → 메모리 폴백. 키 `judge:best`, 값 `{score, seed, inputs}`.
- 온라인 리더보드: stacker와 같은 Supabase REST `fetch` 방식. 테이블 `judge_scores(name, score, seed, created_at)`. 이름 입력은 게임 오버 화면에서 선택적으로. 실패해도 게임은 그대로 돌아야 한다.
- 리더보드 1위 점수를 받아오면 HUD 최고점 옆에 `세계 1위 23,000`으로 표시(원칙 6).

## 7. 자동 플레이 테스트

`window.__judge` 훅을 노출한다:

```js
window.__judge = {
  reset(seed),          // 새 판, 지정 시드
  step(dtFrames),       // 고정 dt로 진행(렌더 없이도 동작)
  tap(),                // 입력
  state(),              // { score, lives, level, active: {color, y} | null, condition, over }
  replay(seed, inputs), // 5장
  DIFFS,
};
```

`test/autoplay.mjs` (Playwright)에 봇 3종:
- **perfect**: 조건 도형이 상단 구역 진입 즉시 탭. 상한 확인용.
- **react(ms)**: 도형이 조건에 맞는지 "본" 뒤 ms만큼 늦게 탭, 5%는 오판. 사람 대역 근사.
- **safe**: 하단 구역에서만 탭. 위험-보상 축이 실제 점수 차이를 내는지 확인(perfect 대비 점수비를 출력).

출력: 봇별 생존 시간·점수·구역 분포를 표로. **이 수치는 밸런스용이고 재미의 증거가 아니다.** README에 그렇게 써둔다.

## 8. 기술 컨벤션 (지침 그대로)

- `index.html` 단일 파일, 빌드 없음, 외부 라이브러리·에셋 없음.
- Canvas 2D + Web Audio 합성. 오디오는 첫 사용자 제스처 후.
- 모든 움직임에 `dt`(60fps 기준 환산, [0, 3] 클램프). `requestAnimationFrame` 시간차로 계산.
- 입력: 터치·마우스·스페이스·엔터 모두 "탭". `touchstart`에 `preventDefault`로 더블탭 줌 방지.
- UI 텍스트 한국어. 시스템 폰트.
- GitHub Pages 자동 배포(`main` 푸시).

## 11. 완료 기준

1. 폰에서 열어 설명 없이 3초 안에 규칙을 이해한다.
2. WRONG 순간 정지 화면만 보고 "내가 뭘 잘못 눌렀는지" 안다.
3. `replay(seed, inputs)` 점수가 원본과 같다.
4. perfect 봇 90초 이상, react(300) 봇 45~75초, safe 봇 점수가 perfect의 40% 이하.
5. 기획자가 직접 10판 플레이한 뒤 실험 기록에 한 줄 남길 수 있다.
