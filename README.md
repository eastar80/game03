# 골라!

> **규칙** 위에서 떨어지는 도형이 지금 조건 색이면 탭한다. 아니면 그냥 보낸다.
> **스킬** 억제(누르지 말 것을 참기) + 반응.

브라우저에서 바로 돌아간다. `index.html` 하나가 전부다. 빌드도, 외부 라이브러리도, 에셋도 없다.

```bash
npx http-server -p 8080 -c-1 .   # 또는 index.html 을 그냥 연다
npm test                          # 자동 플레이 봇 + 재현성 검증
```

---

## 1. 규칙

- 레인 하나. **화면에는 언제나 도형이 하나뿐이다.** 늘 맨 위 HUD 뒤에서 나와 바닥으로 떨어진다.
- HUD 중앙의 **현재 조건**(색 원 + 이름)과 같은 색이면 탭, 다르면 참는다.
- 지금 것이 처리되면(탭했든 바닥에 닿았든) **곧바로 다음 도형이 나온다.** 타이머가 아니다.

| 상황 | 결과 |
|---|---|
| 탭 · 색이 조건과 같음 | **HIT** `+10 × 구역 배율` |
| 탭 · 색이 조건과 다름 | **WRONG** 목숨 −1, 250ms 정지 |
| 안 탭 · 조건 도형이 바닥 도달 | **MISS** 목숨 −1 |
| 안 탭 · 비조건 도형이 바닥 도달 | **PASS** ±0 |

목숨 5개. 0이 되면 게임 오버.
색 4종에는 **색맹 보조 기호**가 함께 들어간다 — 파랑 ●, 빨강 ▲, 노랑 ■, 초록 ◆.

## 2. 점수식 — 그리고 이 게임의 유일한 축

```
HIT 점수 = 10 × 구역 배율
구역 배율 = 탭 순간 도형 중심의 y
            y < 300  →  ×3
            y < 450  →  ×2
            그 외     →  ×1
```

콤보 없음. 아이템 없음. 스테이지 없음. **위험-보상 축 하나뿐이다**(원칙 8).

### y 는 위치가 아니라 시간이다

도형은 언제나 하나이고 언제나 맨 위에서 시작한다. 그래서 **탭한 높이 = 네가 망설인 시간**이다.
구역 경계는 픽셀이 아니라 시간으로 잡았다(활성화된 순간 기준):

| | 레벨 0 | 레벨 5 |
|---|---|---|
| ×3 | 344ms 안 | 235ms 안 |
| ×2 | ~552ms | ~377ms |
| ×1 | ~761ms | ~519ms |
| 그 뒤 | 바닥 = **MISS** | 바닥 = **MISS** |

사람의 색 판단이 대략 300ms 라는 걸 생각하면, **×3 은 확신하기 전에 지르는 것**이다.
그리고 **망설이는 것도 공짜가 아니다** — ×1 구역은 바닥 바로 위이고, 레벨이 오르면
신중한 플레이는 MISS 로 죽는다. 빠르면 WRONG, 느리면 MISS. 그 사이가 스위트 스팟이다.

### 그리고 빠를수록 게임이 빨라진다

다음 도형은 타이머가 아니라 **지금 것이 처리되면** 나온다.
×3 으로 끊으면 다음이 0.4초 뒤에 오고, 바닥까지 흘려보내면 1초 넘게 걸린다.
**배율과 속도가 같은 방향을 가리킨다.** 탐욕이 곧 템포다.

## 3. 난이도 — `DIFFS` 표 하나

레벨은 **처리된 도형 수**로 오른다. 튜닝은 이 표만 고친다.

```js
const DIFFS = [
  // beat: 도형이 처리된 뒤 다음이 나오기까지(프레임). 화면이 완전히 비는 유일한 구간
  { upTo:  15, speed: 12.0, beat: 5, lure: 0.38, switchEvery: 12 },
  { upTo:  35, speed: 13.0, beat: 5, lure: 0.44, switchEvery: 10 },
  { upTo:  60, speed: 14.0, beat: 5, lure: 0.48, switchEvery:  9 },
  { upTo:  90, speed: 15.1, beat: 5, lure: 0.52, switchEvery:  8 },
  { upTo: 130, speed: 16.3, beat: 5, lure: 0.55, switchEvery:  7 },
  { upTo: Infinity, speed: 17.6, beat: 5, lure: 0.55, switchEvery: 6 },
];
```

`speed` 하나가 위 표의 시간 창을 전부 정한다. `beat` 는 도형이 순간이동하지 않게 하는
최소한의 박자(83ms)다. 이 두 값 말고 코어 루프의 속도를 정하는 숫자는 없다.

### 속도-정확도 교환 — 이 게임이 실제로 묻는 것

위 봇은 오판율이 5% 로 고정이라 "빨리 볼수록 더 틀린다"를 못 잡는다.
사람에 가깝게 `오판율 = 2% + 33%·exp(−반응/190ms)` 로 두고 20시드씩 재면:

| 반응 | 오판율 | 생존 | 점수/초 | 평균 배율 | **총점** |
|---|---|---|---|---|---|
| 140ms | 17.8% | 17.8초 | 21.8 | ×3.00 | 388 |
| 200ms | 13.5% | 24.7초 | 21.9 | ×3.00 | 541 |
| 260ms | 10.4% | 33.7초 | 21.3 | ×2.98 | **718** |
| 320ms | 8.1% | 42.4초 | 15.8 | ×2.28 | 670 |
| 400ms | 6.0% | 58.9초 | 13.3 | ×2.00 | **783** |
| 500ms | 4.4% | 71.2초 | 8.9 | ×1.40 | 634 |
| 650ms | 3.1% | 37.6초 | 4.9 | ×1.00 | 184 |

- **양 극단이 모두 진다.** 무모(140ms) 388점, 과신중(650ms) 184점. 260~400ms 사이가 고원이다.
- 650ms 는 생존까지 줄어든다 — 망설이면 MISS 로 죽기 때문. 이게 ×1 구역을 바닥에 붙인 이유다.
- 점수/초가 21.9 → 4.9 로 **4.5배** 벌어진다. 반응 속도가 점수를 정한다.

## 5. 재현성 (원칙 1)

- 게임 로직의 난수는 `mulberry32(seed)` 하나뿐이다. 연출(파편·흔들림)에만 `Math.random` 을 쓴다.
- 시드가 정하는 것: 도형 색 순열, 조건 색, 조건 전환 시점(±1 지터). **결과는 정하지 않는다.**
- **고정 타임스텝**이라 주사율과 무관하게 같은 틱 열을 밟는다. 입력 로그 `[{t: ms}]` 의 `t` 는
  틱 번호와 1:1 대응한다.
- 게임 오버 화면의 `시드 · 재현` 버튼 → `window.__judge.replay(seed, inputs)` 로 다시 돌려
  점수가 같은지 화면·콘솔에 표시하고, 이어서 그 판을 그대로 재생한다.

## 6. 저장 · 리더보드

- 로컬 최고 기록: 어댑터(`window.storage` → `localStorage` → 메모리), 키 `judge:best`,
  값 `{score, seed, inputs}`.
- 온라인 리더보드는 Supabase REST `fetch`. **지금은 꺼져 있다** — 이 저장소에 붙은
  Supabase 프로젝트가 없어 URL/키가 비어 있다. 켜려면:

  ```js
  window.__judgeLB = { url: 'https://xxxx.supabase.co', key: '<anon key>' };
  ```

  테이블 `judge_scores(name text, score int, seed text, created_at timestamptz default now())`,
  RLS 는 select/insert 전체 허용. URL 이 비면 네트워크 호출을 아예 하지 않고,
  켠 뒤 실패해도 게임은 그대로 돈다.
- 1위를 받아오면 HUD 왼쪽에 `세계 1위 23,000` 으로 **플레이 중** 표시한다(원칙 6).

## 8. 하지 않은 것 (원칙 9)

콤보, 연속 보너스, 아이템, 스테이지, 캐릭터, 업그레이드, 모양 조건, 복합 조건, 부정 조건 —
전부 없다. 코어 루프가 재미있다고 확인되기 전에는 붙이지 않는다.

### 다음에 시험해 볼 것 (코드 말고 여기에만 적는다)

1. **총점 고원이 260~400ms 로 넓다.** 여러 스타일이 다 살아 있다는 뜻이라 나쁘지 않지만,
   "지르는 쪽이 이긴다"를 원하면 ×3 배율을 올리는 것(×3 → ×4)이 가장 직접적인 노브다.
   단 `×3` 은 타이틀·배너·라벨에 전부 박혀 있어 표기까지 같이 바뀐다.
2. **`beat` 를 플레이어가 줄일 수 있게 할 것인가.** 지금은 고정 83ms 다.
   ×3 으로 끊었을 때만 더 짧게 하면 "탐욕 = 템포"가 더 세진다. 시스템이 하나 느는 셈이라 보류.
3. **목숨 5개가 맞는가.** 45~90초를 맞추려고 정한 값이다. 판 길이를 다르게 원하면 여기가 노브다.

## 9. 플레이테스트 기록

### 1차 — 규칙 전달 실패

> "아래쪽에 틀린 도형이 있고 위에 맞는 도형이 나올 때 위쪽 도형을 선택하는 방법을 모르겠어."

요청서를 쓴 사람이 자기 게임의 조작을 못 찾았다. 완료 기준 1(설명 없이 3초)과 원칙 3 위반.
게다가 위엣것을 노려 탭하면 아래 틀린 도형이 눌려 목숨이 깎였다 —
규칙을 모르는 사람이 규칙을 배워야 할 순간에 처벌만 받는 최악의 실패 방식.

판정 커서(`▶ ◀`), 대기 도형 축소, 상시 안내, 틀린 순간 교습을 넣어 규칙을 네 겹으로 말하게 했다.
전부 연출 계층이라 봇 수치·재현성은 그대로였다.

### 2차 — 「너무 루즈하고 지루해」 → 코어 루프 교체

> "그럼 결국 1배에서 선택하는 것인데 너무 루즈하고 지루해."

**느낌을 숫자로 바꿔보니 그대로였다.** 사람 모델(반응 300ms)로 90초를 재면:

| | 시간 배분 |
|---|---|
| 칠 수 있음 | **19%** |
| 막혀서 대기 | 54% |
| 빈 화면 / 전환 | 27% |

**시간의 80%가 할 일이 없었다.** 그리고 배율은 이랬다:

- 나는 `speed×gap > 200px` 을 **반응 0ms 인 perfect 봇** 기준으로 맞췄다.
  반응 300ms 인 사람은 60~70px 아래에서 누르므로 같은 상황이 ×1 이 된다.
  **봇 기준은 통과했는데 사람 기준은 실패한 것이다.** 내 튜닝 실수다.
- 더 나쁜 것: ×3 이 나오는 순간은 화면이 비어 있을 때, 즉 **위험이 하나도 없을 때**였다.
  실제 판단은 아래쪽 ×1 에서 일어났다. **위험-보상 축이 뒤집혀 있었다.**

`DIFFS` 만으로 고칠 수 있는지 5개 후보를 재봤다. 못 고친다:

| | ×3 창 | ×3 비율 | 빈 시간 |
|---|---|---|---|
| 현재 3.4/64 | 477ms | 45% | 80% |
| 7.0/44 | 232ms | **0%** | 74% |
| 11.0/36 | 147ms | **0%** | 70% |
| 13.0/33 | 125ms | **0%** | 69% |

속도를 올리면 ×3 창이 반응 시간보다 짧아져 ×3 이 아예 사라지고, 빈 시간은 거의 안 준다.
계산으로도 막힌다 — 막힌 대기 시간 = `gap` 프레임인데, 사람이 ×2 를 잡으려면
`speed×gap > 200 + speed×18` 이 필요하다. **대기를 줄이려면 속도를 올려야 하고,
속도를 올리면 줄이 아예 안 생긴다.** 줄 자체가 문제였다.

**근본 원인:** 배율은 화면 위치로 재는데 플레이어의 시계는 "칠 수 있게 된 순간"부터 간다.
줄이 그 둘을 갈라놔서, 배율이 "내가 얼마나 빨랐나"가 아니라
"화면이 얼마나 비어 있었나"를 재고 있었다.

**고친 것: 화면에 도형을 하나만 두고, 다음 도형을 타이머가 아니라 처리 즉시 내보낸다.**
그러면 y 와 "망설인 시간"이 다시 같은 것이 된다.

| | 이전 | 지금 |
|---|---|---|
| 점수/초 (사람 260ms) | 9.7 | **21.3** |
